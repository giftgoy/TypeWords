# 目标词背诵短文与沉浸式阅读

## 写作流程

在 `/reading-studio` 从任一随附英语词库、自建词库或收藏词库选词，也可以用逗号或换行输入。
模型生成 120–180 词、B1–B2 难度、1–2 个连贯段落的短文，包含标题、目标词加粗的英文、逐段自然中文翻译、目标词原形与文中形式及语境释义、3–5个搭配/句型、一句话主题和适用场景。

服务端校验长度、目标词清单、段落对应、词形和搭配是否实际出现在正文中；前端另外核对词形与原形的对应。未达标时显示错误，不保存为文章。语义与教学质量仍需要学习者审阅，可重新生成。
“保存并进入沉浸式阅读”把文章保存到“我的背诵短文”，复用现有学习数据持久化。可导出目标词加粗的Markdown。

## 模型配置

展开“模型设置”，填写接口、模型和密钥。密钥只在本机typewords-reading服务的持久化卷中保存；状态接口不返回密钥。同一服务更新时留空保留原密钥，切换服务主机或端口时必须填写新密钥。
默认接口为 `https://opencode.ai/inference/go/openai/v1/chat/completions`，默认模型 `glm-5.3-flash`。
通过官方 `/inference/go/v1/models` 动态获取全部模型；可刷新或自定义模型ID。其他兼容服务使用其 `/models` 接口。

官方说明：https://opencode.ai/docs/go/ 。Go主要面向编程代理流量；应用使用真实标识TypeWords-Reading/1.0，不伪装其他客户端。服务拒绝时显示状态码，可更换兼容服务。

启动后端：`docker compose up -d --build reading`。此命令只更新阅读后端；前端Docker需要另行构建typewords。
开发端 `/api/reading/` 代理到本机5568，TTS代理到现有Docker前端5567；Docker内nginx直接代理reading和tts服务。

## 阅读功能

- 第4种正文模式，常显入口；退出回到卡片对照。
- 宽屏目录靠导航，正文以屏幕中线居中；窄屏收起目录，保留切篇选择框。
- 英中自然段对照，缩进2em、浅色虚线分隔。
- 目标词蓝色加粗、底部42%黄底。注音11px，重叠按12px错层；可隐藏并收紧行距。
- 覆盖全部14个随附英语词库，共15,863个不重复词条；自建词库动态加载，可任选词库作为目标范围。
- 正文点击查词、发音、收藏；本地词库命中时无需外部查词服务器。
- “校准语境释义与搭配”按段落与出现序号区分多义词，结果缓存到学习存储。生成短文自带文中释义；未经校准的词典释义明确标识。
- 搭配支持词形变化和一个插入副词，模型补充更复杂的实际片段。点击清单平滑居中并绿色闪烁1.5秒。
- 单词表按正文顺序聚合，同词不同义分行；手机隐藏音标列。

## 播放

全文优先播放原音频，无原音频时使用自然人声TTS逐句朗读，失败时回退浏览器语音。
支持段落播放、暂停续播、停止、语速、当前段落高亮与可关闭的自动跟随。
原音频有有效时间轴时可同步定位；没有时间轴时不能准确推断段落，页面会提示，分段播放使用TTS。
切篇、退出模式及卸载组件会停止播放并释放临时URL。

## 验证

- Node22.18+：`node --test tests/*.test.mjs`；较低版本需`--experimental-strip-types`。
- 后端：复制测试文件到容器/app后，`docker exec typewords-reading python -m unittest test_validation test_server -v`。测试使用临时配置与模拟模型，不读真实密钥。
- OpenCode Go真实生成：5个测试目标词得到139词、2段短文，6条词形释义、5个实际搭配。
- 浏览器检查播放、暂停续播、语速、查词、非CET词库选择、手机切篇和横向溢出。
